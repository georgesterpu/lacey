## Production code versus catalogue data

Automatic Vercel deployment from `main` remains disabled. `bun run release`
requires passing exact-revision CI, stages without assigning the live domain,
checks the database and browser, promotes that build, and rolls back if the
public browser check fails.

The remaining gap was that GitHub's data writers checked out current `main`,
even before a release. Refresh and retention jobs now resolve the live build's
embedded revision through `/api/health`, require a successful quality workflow
for exactly that SHA, then check out that SHA before receiving database
credentials. Missing or failed evidence stops the writer. A newer failed main
branch therefore cannot silently become the scheduled production importer.
The resolver has no production database or email credentials.

Build revision is embedded at build time; the release gate verifies it on both
the staged and public deployment. Do not spoof it with a runtime environment
variable or reset member data to recover an import.

| Workflow | Trigger, Dublin time | Production effect |
| --- | --- | --- |
| Parser and delivery checks | Push, pull request, manual | Tests/builds isolated fixtures; no deployment |
| Price refresh and email alerts | 08:00, 20:00; catch-up at :15 | Imports validated offers and sends eligible digests using the released code |
| Live website check | 08:07, 08:22, 20:07, 20:22 | Read-only browser/API checks |
| Catalogue retention | 03:00 | Removes expired operational data using the released code; preserves active watches |

GitHub can delay scheduled events substantially: the two failed runs arrived
at 16:46 and 17:12 UTC. These schedules are targets, not an exact-time guarantee.
No language model or agent runs the scheduled work.

A release gate protects code publication. It cannot guarantee retailer access
or prevent valid offers expiring. Failed imports preserve the published pointer;
independent freshness limits and source statuses control what remains visible
and eligible for email. Never widen expiry or label old stock as newly checked
just to make a workflow green.
